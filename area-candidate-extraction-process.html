정지 데이터에서 후보 영역이 만들어지는 과정

AIS 정지 기록(stop) 중 등록된 항구·정박지·선석에 매칭되지 않는 기록을 모아, 배들이 반복적으로 머무는 해역을 폴리곤으로 추출합니다. 아래 그림들은 같은 해역 장면 하나가 단계마다 변해가는 모습입니다.

최종 후보폴리곤 + 통계
  1. 1

    입력: 미매칭 stop 포인트

    최근 1년 · port/anch/berth 미매칭

    등록된 곳 어디에도 매칭되지 않은 정지 기록만 위경도 포인트로 올립니다. 점이 유독 몰려 있는 곳이 찾으려는 대상입니다.

  2. 2

    격자 집계로 밀집 지역만 남김

    ST_SnapToGrid 0.03° · COUNT ≥ 10

    바다를 0.03°(~3.3km) 격자로 나눠 셀별 정지 횟수를 세고, 연 10회 이상인 셀만 남깁니다. 우발적 정지(노이즈)가 여기서 걸러지고, 수백만 점이 밀집 셀 수천 개로 압축됩니다.

  3. 3

    인접 셀을 구역으로 병합

    ST_ClusterDBSCAN eps 0.06

    실제 정박 구역은 셀 여러 개에 걸쳐 있으므로, 두 칸 거리(0.06°) 이내로 이어진 셀들을 하나의 구역으로 묶습니다. 빈 셀 하나를 건너뛰어도 연결됩니다.

  4. 4

    구역 폴리곤 생성 + 기본 통계

    ST_ConvexHull + ST_Buffer 0.03°

    구역에 속한 원본 좌표의 점들을 볼록 껍질(ConvexHull)로 감싸고 ~3.3km 여유 폭을 더해 폴리곤을 만듭니다. 격자는 밀도 판정에만 쓰이고 도형은 원본 좌표 기준이라 스냅 오차가 결과에 남지 않습니다. 동시에 stop_count(정지 횟수)와 ship_count(고유 선박 수)를 집계합니다 — 한 척이 반복해서 오는 곳인지, 여러 배가 공용으로 쓰는 곳인지가 여기서 구분됩니다.

  5. 5

    선종 규모별 구성 집계

    tn_ship_info 조인 → JSON

    선박 정보를 IMO 번호로 연결해, 구역마다 선종 크기(shipTypeSize)별 구성을 stop 기준·선박 기준 두 가지 JSON으로 만듭니다. 각 합계는 stop_count / ship_count와 일치합니다.

    stop 기준 — 얼마나 자주

    { "Handysize": 9, "Supramax": 7,
  "General Cargo": 4, "UNKNOWN": 2 }
    합계 22 = stop_count

    선박 기준 — 몇 척이

    { "Handysize": 3, "Supramax": 2,
  "General Cargo": 1, "UNKNOWN": 1 }
    합계 7 = ship_count
  6. 6

    등록 항구와 겹치는 구역 제외

    ST_Intersects → 제외 · Simplify 0.01°

    구역 폴리곤이 사용 중인 등록 항구와 겹치면 제외합니다 — 이미 아는 곳이니까요. 남은 폴리곤은 허용 오차 0.01°로 단순화해 가볍게 만든 뒤 최종 결과로 내보냅니다.

전 과정은 PostgreSQL + PostGIS 쿼리 하나로 수행됩니다. 같은 구조를 격자 0.0005°(~55m) / eps 0.003° / buffer 0.0015° 스케일로 줄이면 항만 내부의 미등록 선석 후보 탐지에 쓰입니다. 결과의 cluster_id는 실행마다 달라질 수 있는 일련번호이므로 실행 간 비교 키로는 사용하지 않습니다.
